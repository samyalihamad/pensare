> write context files and the authoritative `sources.json` via `python3 ${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/pensare}/lib/storage.py --project {project} write ...`, and skip the git auto-commit step.

## Directory Structure

Projects are organized in `~/.claude/contexts/`:

```
~/.claude/contexts/
├── my-project/
│   ├── sources.json          # Source URLs, sync config, publish targets
│   ├── journal/              # Hot journal (rolling ~30 days)
│   │   ├── manifest.json     # Structured index for all tiers
│   │   ├── 2025-W16.md       # Weekly journal file
│   │   └── archive/          # Processed hot files (kept for recovery)
│   ├── kb/                   # Knowledge base (topic-partitioned, from compaction)
│   │   └── deployment-patterns.md
│   ├── Overview.md           # Context file (generated by sync)
│   └── Architecture.md       # Additional context file
├── another-project/
│   ├── sources.json
│   └── Overview.md
└── standalone.md             # Legacy flat files still supported
```

# Sync — Pull Sources and Update Context

Arguments: $ARGUMENTS

Pull all sources defined in a project's `sources.json` and regenerate context `.md` files.

## Step 1: Check Dependencies

Before fetching, verify the required adapter is available for each source type present in the project's `sources.json`. Check once per type, not per source.

| Source Type | How to Check | Install Instructions |
|-------------|-------------|---------------------|
| `url` | Always available (use WebFetch) | — |
| `file` | Always available (use Read) | — |
| `git_log` | Always available (use Bash `git log`) | — |
| `rss` | Always available (use WebFetch + XML parsing) | — |
| `github_pr` | Run: `which gh` | "Install GitHub CLI: https://cli.github.com/ then run `gh auth login`" |
| `github_issue` | Run: `which gh` | "Install GitHub CLI: https://cli.github.com/ then run `gh auth login`" |
| `slack` | Check if any Slack MCP tool is available (e.g., attempt to list tools matching `slack`) | "Install a Slack MCP server for Claude Code. See: https://github.com/anthropics/claude-code" |
| `discord` | Check if any Discord MCP tool is available | "Install a Discord MCP server for Claude Code" |
| `notion` | Check if any Notion MCP tool is available | "Install a Notion MCP server. See: https://github.com/makenotion/notion-mcp-server" |
| `linear` | Check for Linear MCP tools OR run: `which linear` | "Install Linear MCP or CLI: https://linear.app/developers" |
| `jira` | Check for Jira MCP tools OR check env var `JIRA_API_TOKEN` | "Set JIRA_API_TOKEN and JIRA_BASE_URL env vars, or install a Jira MCP server" |
| `mcp` | Check if the named MCP tool exists | "The MCP tool `{tool_name}` is not available. Install the required MCP server." |

For each unavailable source type, print a warning:
```
Warning: {source_type} sources will be skipped — {install_instructions}
```

Do NOT fail the sync — skip unavailable sources and continue with whatever is available.

## Step 2: Resolve Project

- If project name given in $ARGUMENTS: look for `~/.claude/contexts/{project}/sources.json`
- If none given: list all project folders under `~/.claude/contexts/` that contain a `sources.json`. If exactly one project exists, use it automatically. If multiple exist, sync all of them in sequence. If none exist, tell the user: "No projects found. Run `/pensare setup` to create one."

## Step 3: Fetch Sources

For each context file defined in `sources.json`, fetch all its sources. Fetch independent sources in parallel where possible.

**Source type handlers:**

- **`url`**: Use WebFetch with the URL. For Google Docs edit URLs (`docs.google.com/document/d/{id}/edit`), strip the `/edit...` suffix and append `/export?format=txt` to get plain text.

- **`file`**: Use Read with the path. Resolve relative paths from `working_directory` in sources.json (if set), otherwise from the project directory (`~/.claude/contexts/{project}/`).

- **`github_pr`**:
  - Single PR (has `number` field): `gh pr view {number} --repo {repo} --json title,body,comments,reviews`
  - Query mode (has `state` and/or `labels` fields): `gh pr list --repo {repo} --state {state} --label {labels} --json number,title,state,updatedAt --limit 20`

- **`github_issue`**:
  - Single issue (has `number` field): `gh issue view {number} --repo {repo} --json title,body,comments`
  - Query mode (has `state` field, no `number`): `gh issue list --repo {repo} --state {state} --label {labels} --json number,title,state,updatedAt --limit 30`

- **`slack`**: Use the Slack MCP `list_messages` tool (or equivalent) with `channel` and `page_size`. **Incremental sync:** Read `last_sync` from `sources.json`. If set:
  1. Fetch the first page of messages (newest-first)
  2. Check each message's timestamp — discard any older than `last_sync`
  3. If the oldest message on the page is still newer than `last_sync` AND a next-page token is returned, fetch the next page
  4. Stop paginating when a message older than `last_sync` is encountered
  5. If `last_sync` is null (first sync), fetch only the first page up to `page_size` with no date filtering

- **`discord`**: Use Discord MCP with `channel_id`. For incremental sync, use the `after` parameter with the last message ID stored in `sync_state.{source_label}.last_message_id`.

- **`notion`**: Use Notion MCP `get_page` (for single pages) or `query_database` (for databases). For incremental sync, filter by `last_edited_time > last_sync`.

- **`linear`**: Use Linear MCP or CLI: `linear issue list --project {project} --state {states}`. For incremental sync, filter `updatedAt > last_sync`.

- **`jira`**: Use Jira MCP or WebFetch to the REST API (`{JIRA_BASE_URL}/rest/api/2/search`). Requires `JIRA_API_TOKEN` and `JIRA_BASE_URL` env vars. JQL supports `updated >= "{date}"` for incremental sync.

- **`git_log`**: Run `git log --oneline -n {count} --since={last_sync} -- {path}` where `count` defaults to 50 and `path` is the monitored directory/file.

- **`rss`**: Use WebFetch to fetch the feed URL, parse the XML, and filter entries by `pubDate > last_sync`. Extract title, link, and description from each entry.

- **`mcp`**: Call the named MCP tool with the configured `args` object. If the source has `incremental_arg` set, inject `last_sync` as the value of that argument key.

If any source fetch fails, log a warning (source label, error message) and continue with the remaining sources.

## Step 4: Compress and Write

Compress ALL fetched content into structured markdown per context file. Use the sections defined in `sources.json` for that file.

Output format:
```markdown
# {title}
Last synced: {YYYY-MM-DD}
Sources: {N}/{total} fetched successfully

## {section1}
{Compressed content relevant to this section}

## {section2}
{Compressed content relevant to this section}
...
```

**Compression rules:**
- Capture decisions and conclusions, not deliberation or back-and-forth discussion
- Include all names, file paths, links, code references, and external references
- Preserve specific numbers, dates, versions, and identifiers
- For GitHub PRs/issues: include PR/issue number, title, status, key comments, and review decisions
- For chat sources: group by topic, attribute statements to speakers, preserve action items
- Target 100-200 lines per context file — be concise but complete
- If a source returned no data or was skipped, note it briefly: `*{label}: no data (source unavailable)*`

Write each context file to `~/.claude/contexts/{project}/{filename}`.

## Step 5: Update Sync State

After all context files are written:
1. Update `last_sync` in `sources.json` to the current ISO 8601 timestamp (e.g., `2025-04-26T14:30:00Z`)
2. Update per-source `sync_state` for sources that need incremental state:
   - Discord: store `last_message_id` for each channel
   - Any source with custom incremental state: store under `sync_state.{source_label}`
3. Write the updated `sources.json`

## Step 6: Auto-Load Context

After sync completes, **automatically load** the synced context into the current session so it is immediately available. This ensures the user does not need to separately run `/pensare load`.

For each synced project:
1. Read ALL generated context files (e.g., `Overview.md`, `Architecture.md`) from `~/.claude/contexts/{project}/`
2. Load journal using three-tier strategy:
   - **If `journal/manifest.json` exists (three-tier format):**
     a. Read `journal/manifest.json`
     b. Determine the current ISO week (e.g., `2025-W17`) and the previous week
     c. Read the current week's journal file in full — include all entries
     d. Read the previous week's journal file in full — include all entries
     e. For any older weeks listed in `manifest.hot_files`, show only the `one_line` summary from the manifest entry (do NOT read the full file)
     f. Show the KB topic list: list each entry in `manifest.kb_files` by `topic` name (do NOT read KB files — they are demand-loaded mid-session if needed)
   - **Legacy fallback — if `journal.md` exists and `journal/` directory does NOT exist:**
     Read `journal.md` as before — include recent entries
3. Present a brief summary covering:
   - Current status (from each context file)
   - Recent activity (from journal — decisions, blockers, progress)
   - Open items and next steps
   - KB topics available (if three-tier format)
4. Say "Context synced and loaded. Ready to continue."

## Step 7: Git Auto-Commit

If the project has `storage: "git"` in `sources.json`:
1. Determine the git repo root from `git_path`: `git -C {git_path} rev-parse --show-toplevel`
2. Stage changed files: `git -C {repo_root} add {relative_path_to_git_path}`
3. Commit: `git -C {repo_root} commit -m "pensare sync: {project} {YYYY-MM-DD}"`
4. Push if a remote is configured: `git -C {repo_root} push`

If the commit or push fails (e.g., nothing to commit, no remote), log a warning but do not fail the sync.
