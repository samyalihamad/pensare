> **S3-backed projects** (see the **Storage backend** rule): if `sources.json` has `storage: "s3"`,
> read source content (journal/kb/context files) via `python3 ${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/pensare}/lib/storage.py --project {project} read|dump ...`. The publish target (the shared git plan file) is written with the normal tools as usual.

## Directory Structure

Projects are organized in `~/.claude/contexts/`:

```
~/.claude/contexts/
├── my-project/
│   ├── sources.json          # Source URLs, sync config, publish targets
│   ├── journal/              # Hot journal (rolling ~30 days)
│   │   ├── manifest.json     # Structured index for all tiers
│   │   ├── 2026-W17.md       # Weekly journal file
│   │   └── archive/          # Processed hot files (kept for recovery)
│   ├── kb/                   # Knowledge base (topic-partitioned, from compaction)
│   │   └── auth-migration.md
│   └── Overview.md           # Context file (generated by sync)
├── another-project/
│   ├── sources.json
│   └── Plan.md
└── standalone.md             # Legacy flat files still supported
```

# Publish — Push to Plan Files

Arguments: $ARGUMENTS

Push mature local context and journal entries to source-controlled plan files.

## Steps

### 1. Resolve Project and Target

Auto-resolve project (session context, single project, or ask). Read `publish_targets` from `sources.json`. If no `publish_targets` configured, tell the user: "No publish targets configured in sources.json. Add a `publish_targets` section to enable publishing." and stop. If argument given (e.g., "Plan"), only publish matching target.

### 2. Read ALL Sources

Read every one of these (missing OK, skip):
- Journal: all hot files from `journal/` + KB files from `kb/`
- Context files (*.md in project root)
- Target plan file (to see current content and preserve unchanged sections)

### 3. Compose Per Section

For each section in `publish_targets.sections`, compose content from journal + context. Use structured formatting appropriate to the content type. Synthesize — don't just concatenate raw entries. Use date headers, tables, and bullet lists as appropriate.

### 4. Preview and Confirm

BEFORE writing, show full composed content. Print "Publish these changes? (y/n)". Wait for explicit user confirmation. NEVER auto-write.

### 5. Write and Report

If confirmed: update section in-place or append to plan file.

If git mode (`storage: "git"` in `sources.json`):
```bash
cd {git_path} && git add {plan_file} && git commit -m "pensare publish: {section_name}" && git push
```

Otherwise: "Changes are local only. Run `git commit` to save."
