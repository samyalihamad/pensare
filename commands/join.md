## Directory Structure

Projects are organized in `~/.claude/contexts/`:

```
~/.claude/contexts/
├── my-project/
│   ├── sources.json          # Source URLs, sync config, publish targets
│   ├── journal/              # Hot journal (rolling ~30 days)
│   │   ├── manifest.json     # Structured index for all tiers
│   │   ├── 2025-W16.md       # Weekly journal file
│   │   └── archive/          # Processed hot files (kept for recovery)
│   ├── kb/                   # Knowledge base (topic-partitioned, from compaction)
│   │   └── deployment-patterns.md
│   ├── Overview.md           # Context file (generated by sync)
│   └── Architecture.md       # Additional context file
├── another-project/
│   ├── sources.json
│   └── Overview.md
└── standalone.md             # Legacy flat files still supported
```

# Join — IC Onboarding

Arguments: $ARGUMENTS

Streamlined onboarding for ICs joining an existing project. Instead of the full setup wizard, `join` reads the shared team config from `.pensare/` in the team folder and creates a local project with minimal interaction.

**When to use:** The TL runs `/pensare setup` once and commits `.pensare/` to the team folder. Everyone else runs `/pensare join` with the team folder path.

#### Step 1: Resolve Team Folder Path
Extract the path from $ARGUMENTS. Accept these formats and resolve to a local filesystem path:

- **Local path:** `~/projects/my-app/plans/` — use as-is (expand `~`)
- **Absolute path:** `/home/user/projects/my-app/plans/` — use as-is
- **GitHub URL:** `https://github.com/org/repo/tree/main/plans/` — check if `org/repo` has a local checkout by running `git remote -v` in likely locations (current directory, `~/projects/`, `~/repos/`). If found, resolve to the local path. If not found, ask the user to clone the repo first: "Could not find a local checkout of `org/repo`. Clone it first, then re-run with the local path."
- **Repo-relative path:** `docs/plans/` — resolve from the current git repo root (`git rev-parse --show-toplevel`)
- **Natural language:** "join the project at ..." — extract the path/URL from the sentence, then resolve using rules above

If no path is given, ask: "What is the team folder path? (e.g., `~/projects/my-app/plans/` or a repo-relative path like `docs/plans/`)"

#### Step 2: Read Shared Config
Check for `{team_folder}/.pensare/` directory. It must contain at least `sources-base.json`.

If `.pensare/` is not found:
```
No shared team config found at {team_folder}/.pensare/
Ask your TL to run `/pensare setup` and commit the .pensare/ directory.
Or run `/pensare setup` yourself to create the project from scratch.
```
Stop here.

Read the shared config files:
- **`sources-base.json`** (required): Contains `project_name`, `context_files` (with sources and sections), and optionally `publish_targets`
- **`reconcile.json`** (optional): Contains `plans_dir`, `contracts_file`, `components`, `monitored_paths`

#### Step 3: Check for Existing Project
Check if `~/.claude/contexts/{project_name}/` already exists.
- If yes: "Project `{project_name}` already exists locally. Run `/pensare sync` to update, or delete `~/.claude/contexts/{project_name}/` to start fresh."
- Stop here.

#### Step 4: Select Component
If `reconcile.json` exists and has components, display them:

```
This project has {N} components:

  1. API Service              (Alice Chen)     [MY-PROJ:API]
  2. Dashboard                (Bob Martinez)   [MY-PROJ:DASH]
  3. Data Pipeline            (Carol Wu)       [MY-PROJ:DATA]

Which component are you working on? (enter number, or press enter for full project)
```

Store the selected component — used for:
- Setting the user's default `publish_targets` to their component's plan file
- Pre-filtering journal views to their component's tag

If user skips, they get the full project config (same as the TL).

#### Step 5: Personal Sources (Optional)
Ask: "Any personal sources to add? (e.g., your own Slack channel, a doc you're tracking)
Paste URLs — one per line. Press enter twice to skip."

Parse inputs the same way as `setup` Step 6:
- GitHub PR/issue URLs → `type: "github_pr"` or `type: "github_issue"`
- Slack URLs → `type: "slack"`
- Notion URLs → `type: "notion"`
- Google Docs URLs → `type: "url"` (with export transform)
- Local file paths → `type: "file"`
- Other URLs → `type: "url"`

Append these to the sources from `sources-base.json`.

#### Step 6: Create Project
1. Create directory `~/.claude/contexts/{project_name}/`
2. Build `sources.json` by merging:
   - `context_files` from `sources-base.json` (with any personal sources appended)
   - `publish_targets` from `sources-base.json` (or scoped to selected component's plan file)
   - `team_dir` set to the team folder path
   - `joined_component` set to the selected component name (if any)

   **Do NOT copy reconcile config into sources.json.** Reconcile config stays in the shared `{team_dir}/.pensare/reconcile.json` — all team members read from the same file at runtime.
3. Write `sources.json`
4. Create three-tier journal structure:
   - `mkdir -p ~/.claude/contexts/{project_name}/journal/ ~/.claude/contexts/{project_name}/kb/`
   - Write `journal/manifest.json`:
     ```json
     {"version": 1, "hot_retention_days": 30, "hot_files": [], "kb_files": [], "last_compaction": null, "compaction_in_progress": false, "legacy_journal_migrated": false}
     ```

#### Step 7: Sync and Report
Print summary:
```
Project joined: {project_name}
Component: {selected_component or "all"}
Sources: {N} from team config + {M} personal
Team folder: {team_folder}
```

Offer to run initial sync: "Run `/pensare sync` now to pull sources? (y/n)"

If yes, run the sync flow (same as `/pensare sync {project_name}`).
